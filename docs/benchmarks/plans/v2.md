## Scope and authority

This plan specifies implementation work and acceptance evidence for the two P0 and five P1 suites in [SPEC-GOV-004](../../governance/SPEC-GOV-004-benchmarking-plan.md). The [requirements suite matrix](../../development/requirements.md#phase-16-alignment-with-spec-gov-004-benchmark-suites) remains the implementation/evidence status index. GOV-004 remains the policy authority. This document version is an implementation-plan revision, not a new artifact schema or public API version.

Scaling runner and shared measurement support are implemented; campaign evidence is tracked below. Other work remains planned unless explicitly described as existing. Writing this plan closes no measurement or release gate. Preserve the [initial Phase 16 archive](../evidence/phase16-e171c584e8e67215f1e5fb00f6f908d2e434b10c/README.md), its commands, and its local evidence classification. P2 noise/cluster implementation, Phase 14 model extensions, and Phase 18 deployment work are outside this plan.

Agreed scale targets are **20 atoms for P0 scaling and P1 MWIS/UDG and open-system campaigns**. GPU scanning also targets a bounded chain series through 20. Full dense, full sparse construction, and Lindblad execution retain separate resource limits. Report atom count and actual basis dimension together; a 20-atom reduced scenario establishes evidence only for that geometry, radius, and configuration.

## Shared measurement implementation

### Campaign freeze and defaults

Reuse `benchmarking.py`, `benchmark_row_contract.py`, `benchmark_failures.py`, and `benchmark_suite.py`. Add only the small shared helpers needed for timing, summaries, resource supervision, and retention; do not introduce a general scheduler.

Before measurement, retain a campaign record with an ordered scenario list, config hash, exact commands/working directory, protocol/plan versions, timeout and memory limits, stop policy, reference type and tolerances, seed lists, and required/optional scenario classification. Record physical units, register coordinates/order, C6, pulse parameters, initial state, basis/radius, solver, output times, observables, precision, CPU/BLAS/Julia threads, backend/device, container, versions, commit and dirty state. Hashing identifies a configuration; replay also requires its retained values.

The following are campaign defaults. Scaling implements the applicable timing, solver/grid and resource controls documented below; flags for other suites remain planned until their runners land. Freeze final values before measurement and record deviations and reasons.

| Setting | Plan default | Interpretation |
| :--- | :--- | :--- |
| Warmup runs | 2 per scenario/path | Separate from measurements; GOV-004 recommends 1–3. |
| Measured repeats | At least 5 | Independent executions of one frozen workload. |
| Matvec operations per repeat | 50 | Batch size, separate from measured repeats. |
| Deterministic input seed | 1234 | Reuse identical inputs across paths and timing repeats. |
| Statistical seed set | Five retained seeds, initially 20260811–20260815 | Separate convergence study; seeds are not timing-repeat indices. |
| Common solver anchor | Tsit5, adaptive, reltol=1e-8, abstol=1e-10 | Suite-specific scenarios may override explicitly. |
| Common output grid | 101 explicit equally spaced points including endpoints | Retain normalized effective times and actual sample count. |
| Reference error targets | Declared per suite below | Pilot-confirm targets, then freeze before governed measurement. |

Select numerical wall-time and memory limits for the actual host during preflight and persist them before execution. Use resource estimates for construction as well as state storage. Do not launch an allocation already estimated to exceed the declared budget. Keep an explicit row for each budget exclusion and attempted failure.

### Timing and statistics

1. Run initialized CPU/backend diagnostics; CUDA requires opt-in and successful initialized CUDA doctor.
2. Measure setup/JIT, basis/operator construction, and first solve separately where material. Record cache policy and whether validation/preflight warmed construction or backend state. A first solve after doctor is not process-cold initialization.
3. Warm each measured path using its actual scenario. Reset state and fixed random input before every independent repeat.
4. Time the declared solve or matvec batch. Exclude reference computation, numerical validation, artifact writes, and report generation. If the SDK call includes transfers/observable collection, label that end-to-end scope consistently.
5. Validate outputs and save result/manifest/reference links after stopping the solve timer. Keep invalid runs as diagnostic rows.
6. Retain per-repeat rows and compute median/min/max/p25/p75 from the eligible measured repeats only. Retain requested/completed/eligible repeat counts and the quantile convention. Predeclare exclusions; never remove a slow valid repeat as an outlier.

Do not pool different sizes, seeds, workloads, implementations, or precision settings into one runtime summary. Timing repetition at a fixed stochastic seed measures execution variability. Independent seed sets measure sampling variability. Comparisons require matching numerical accuracy and declared workload boundaries.

### Memory and failure supervision

Use a supervised child process per scenario/path when collecting independent peak process memory. Warm and repeat within that process; retain process-lifetime peak, baseline, measurement method, and scope. `current_memory_usage()` exposes historical process `max_rss`; repeated snapshots in a shared process do not establish separate per-case peaks. Normalize units while retaining source units. CPU and CUDA paths must have attributable memory records.

GPU before/after snapshots are snapshots, not measured peaks. Record peak GPU memory only when a supported measurement actually provides it; retain unavailable values and reasons. Account for caches and other device users in interpretation.

The supervisor must preserve rows when a child times out, exhausts memory, exits unexpectedly, or cannot finish artifact writing. Planned budget exclusions and disabled optional CUDA are `skipped` with context. Attempted solver/reference/backend failures are `failed`; interrupted or insufficient-repeat evidence is `incomplete`. Use existing status meanings and failure helpers; retain already collected metrics, diagnostic stage/code, limits, probe, exception, and remediation.

### Correctness and evidence levels

Follow the [scientific software SOP](../../development/SOP.md): distinguish software testing, software verification, numerical verification, and scientific validation. Projected dense checks verify a reduced implementation. Physical equivalence to finite-interaction full-space evolution requires separate approximation errors and budgets. Performance evidence requires applicable reference gates, matching Python/Julia golden-test evidence, and sufficient metadata; it does not establish hardware calibration or scientific model validity.

### Implemented measurement boundaries

Each scenario uses a fresh Linux child process with a 600-second wall-time
limit and 4096 MiB sampled RSS budget by default. Construction preflight
includes a 2 GiB Julia/JIT reserve, dimension/atom-dependent cached mapping and
workspace allowances, small dense-reference temporaries and output storage.
Budget exclusions remain skipped. RSS enforcement samples the scenario PID
every 50 ms; brief transients and external dependency precompile workers are
not a hard address-space cap. Kernel process-lifetime HWM and source `max_rss`
are retained separately from supervisor samples, with baseline after doctor.
Memory includes initialization, reference computation and serialization.

CPU Julia/BLAS/OpenMP/MKL threads are fixed to one in child environments;
effective Julia/BLAS counts and runtime project manifests are retained.
The basis timer measures `validate()` after initialized doctor. The first
solve is separate, followed by two actual-scenario warmups. Each timed call
resets the all-ground state. SDK `Simulation.run` timing includes validation,
operator construction, collection and manifest creation; it excludes external
reference work, numerical checks, result writes and reporting. Backend
operator/JIT costs inside that call are not claimed as isolated kernel costs.
`time_s` remains one call (first measured repeat); `median_time_s` and
`metrics.statistics` describe eligible independent repeats using linear
Hyndman-Fan type-7 quantiles. Historical V1 single-run and v2 warm-repeat
boundaries must be identified when comparing artifacts.

Small references independently enumerate bitstrings, assemble full-space H
with Kronecker operators, project onto the executed basis, compare Julia H
at 1e-12, and evolve with an eigendecomposition. Larger references use Tsit5
at reltol=1e-11/abstol=1e-13. The observable gate is frozen per campaign
(default 1e-8). Insufficient warmup/repeat evidence is incomplete; failed
accuracy gates and attempted backend/reference failures are failed. Timeout
and interruption preserve incomplete progress. `coverage.json` distinguishes
selected-scenario success from all 42 v2 scenarios passing.

## P0 ablation

Extend `sagittarius/ablation.py` and `benchmark_ablation.py`. Keep legacy `repeats` as the batch operation count; add an independent measurement count rather than silently changing its meaning.

| :--- | :--- | :--- |

| CPU reduced | `reduced_matrix_free`, `reduced_sparse` | Same projected H, basis, input vector, precision and batch size. |
| Optional CUDA | `reduced_sparse_gpu_cached` | SDK ODE solve, reported separately from matvec. |

Use N=4,8,12 as initial CPU fixtures; extend reduced paths to N=16,20 under the retained resource budget. Anchor a=2.0, C6=100, Rb=3.0, omega=2*pi, delta=0. Preserve the existing full-dimension guard (4096 by default) and add memory preflight. A full path above its guard remains a documented exclusion.

Implementation tasks:

1. Use a fixed normalized seeded input for each H*psi operation; prevent the current repeated H^k*psi growth from confounding finite-value/error checks. Document this workload revision and do not pool old/new measurements.
2. Separate correctness checks from measured batches. Use independent dense/full and projected-dense/reduced references on small fixtures. Start with full relative error <=1e-12 and reduced absolute error <=1e-10; include scale and finite-value checks and pilot-confirm these targets.
3. Record matrix/operator construction separately, then warm and independently repeat each batch. Each row records operation count and time per operation; outer repeats drive runtime statistics.
4. Identify current CPU paths as Python/NumPy/SciPy implementations. Their timings do not characterize Julia solver internals. Current sparse construction materializes dense intermediates; disclose this in construction/memory evidence.
5. CUDA remains optional, doctor-gated and opt-in. Use the GPU suite's matched CPU solve/parity when reporting a solve ratio. Retain first/warm solve boundaries and never form CPU-matvec/CUDA-solve speedups.

Preserve `ablation_bench_results` JSON/CSV/Markdown, optionally adding `ablation_bench_results_suite`. Required small CPU fixtures must pass; optional CUDA skips do not close CUDA measurement scope. Full/reduced timing differences require explicit dimension/approximation context.

Pilot-check numerical resolution, then freeze it. Broader schedule searches, planted/structured families and algorithm-quality optimization are later extensions.

## P1 open-system

Preserve `benchmark_phase16_validation.py` and its archived one-atom fixture. Add the planned `benchmark_open_system_performance.py` and `open_system_performance` artifact/suite. | Axis | Initial coverage |
| :--- | :--- |
| Target sizes | N=1,2,4,6,8,10,12,16,20 |
| Paths | CPU Lindblad and CPU MCWF, full/reduced where allowed |
| Trajectories | 100,500,1000 |
| Models | Decay only, pure dephasing only, combined; scalar anchor plus small per-atom-rate fixture |
| Rates | Initial anchors gamma=0.5, gamma_phi=0.125 in documented time units; zero the unused rate |

| Output | 101 shared explicit times; site populations plus a fixed supported total/pair set |

Use the five retained statistical seeds for convergence, independently from timing repeats. Cover noise types and basis mapping on small systems first; use one frozen combined-noise chain anchor for the extended series, then add selected cases. Freeze geometry, pulse, rates, initial states and duration before measurement.

Resource and correctness policy:

- Preflight every declared target size/path using D and D^2, temporary allocations and output storage. Full-space N=20 complex128 density storage alone is 16 TiB; budget Lindblad independently and preserve excluded rows. Do not require unsafe allocations to record the limit. MCWF/reduced execution also needs actual memory estimates.
- Require small analytic population decay, coherence/dephasing reference, and dense Lindblad checks. Population-only undriven decay does not validate pure dephasing; inspect small raw density matrices or a driven observable reference.
- Start with analytic population error <=1e-6, trace error <=1e-6, and min density eigenvalue >=-1e-7. Apply density checks over the saved reference times and retain the raw/reference evidence; do not charge this validation storage/eigendecomposition to the timed observable workload.
- Compare MCWF with Lindblad at matching times wherever tractable. Before the campaign freeze a multi-seed statistical error/uncertainty rule, observables, confidence level and time-point multiplicity treatment. Pilot data tunes sample counts, not post-hoc pass criteria. Per-seed error need not decrease monotonically with trajectory count.
- For larger cases lacking Lindblad reference, retain tighter-solver checks, multi-seed trajectory convergence, and tractable analytic special-case controls at target sizes. Mark the remaining interacting-model reference gap; small-system parity does not establish independent reference verification at N=20.
- Default `store_trajectories=False` for performance. Measure raw trajectory retention separately with its storage metadata, since cost scales with observables, times and trajectory count. Report runtime/memory and completed trajectories per second with the actual serial/threaded execution mode; fixed-seed execution can differ from unseeded execution.

Archive both requested and effective seeds/trajectory counts, noise rates, basis metadata, output grid, result/manifests and convergence reports. The N=20 goal requires successful, applicable reference-gated execution before claiming successful coverage. A budget exclusion documents a boundary and leaves that scope open.

## Completion, recurring runs and maintenance

Track three milestones per suite: runner implemented, declared campaign executed, and acceptance evidence reviewed. Current matrix statuses do not advance on a plan or runner alone. Required small references must pass; optional/budget exclusions and missing measurements stay visible. Every declared target row must be accounted for, and successful coverage requires actual eligible execution. A lower measured limit must be reported as such; changing frozen scope requires an explicit documented decision.

For each RC, rerun and archive both P0 suites with verified companions. For hardware/backend or solver/observable/seed/noise/schema changes, rerun the affected P1 scope under GOV-004. Initial closure, a local campaign and a public performance approval remain separately recorded decisions.
